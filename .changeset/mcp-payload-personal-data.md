Tool arguments, tool results, error messages, exception values, and resource read URIs now have personal data redacted by default, as the intent already did. Emails (an accented local part such as `josé@example.com` included), Luhn-valid card numbers (13 to 19 digits, ungrouped or grouped the way cards are printed: 4-4-4-4, 4-4-4-4-3, 4-6-5, or 4-6-4, by single spaces or dashes), US social security numbers, IPv6 and public IPv4 addresses, and phone numbers written with an international prefix (`+`, `00`, `011`) or a parenthesized area code become `[redacted]`, in string values and object keys at any depth. In a text that parses as JSON, a card number written as a JSON number, `4111111111111111.0` and `4111111111111111e0` included, becomes the string `"[redacted]"`; negative numbers and fractions with digits after the point are kept. In any other text, a log line or a URL included, a card becomes `[redacted]`, unquoted. A JSON or JavaScript string escape (`\n`, `\"`, `\u00e9`) no longer hides an identifier or a PostHog token written right after it, an identifier written with `\uXXXX` escapes (`ada\u0040example.com`, `4111\u00201111\u00201111\u00201111`) is read as the characters they encode, and a JSON text copy of a result is redacted in place, so it keeps its formatting and stays valid JSON. Private, loopback, and link-local addresses, versions written after a letter (`v1.2.3.4`), and `415-555-0142`-style numbers are kept. Some identifiers still read as personal data and are redacted: `ddd-dd-dddd` references (read as social security numbers), a four-part version at the start of a string or after a space, `:`, or `@` (`22.11.0.3`, `node:22.11.0.3`), zero-padded ids starting `00` (`0012345678`, read as an international prefix), `+`-signed numbers and ISO 6709 coordinates (`+1500000000`, `+40.6894-074.0447/`, read as phone numbers), a URL with a user and password (redacted whole), and about 1 in 10 numeric ids of 13 to 19 digits (they pass the card checksum). Argument names these rules would change are no longer listed in `$mcp_input_keys`. If your tools return personal data on purpose, set `redactPayloadPersonalData: false` on `instrument()` or `PostHogMCP`. `beforeSend` can drop a value but cannot restore one. With the option off, the intent and feedback text keep their redaction, and credentials are redacted everywhere. A string longer than four times the captured string limit is redacted on its first part only, the part truncation can keep, so a multi-megabyte tool result costs about what a captured one does. A URL that runs past that part, such as a `data:` image in an HTML page or an address whose user or token sits after it, is now replaced whole by `[redacted]` and nothing after it is captured, with the option on or off. It was read in full before. Object keys in arguments and results are cut to 256 characters, with the option on or off.
