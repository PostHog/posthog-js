Tool arguments, tool results, error messages, exception values, and resource read URIs now have personal data redacted by default, as the intent already did. Emails, Luhn-valid card numbers, US social security numbers, IPv6 and public IPv4 addresses, and phone numbers written with an international prefix (`+`, `00`, `011`) or a parenthesized area code become `[redacted]`, in string values and object keys at any depth. A card number sent as a JSON number becomes the string `"[redacted]"`, so a result's JSON text stays valid JSON. Private, loopback, and link-local addresses, versions written after a letter (`v1.2.3.4`), and `415-555-0142`-style numbers are kept. Some identifiers still read as personal data and are redacted: `ddd-dd-dddd` references (read as social security numbers), a four-part version after a space, `:`, or `@` (`node:22.11.0.3`), a URL with a user and password (redacted whole), and about 1 in 10 numeric ids of 13 to 19 digits (they pass the card checksum). Argument names these rules would change are no longer listed in `$mcp_input_keys`. If your tools return personal data on purpose, set `redactPayloadPersonalData: false` on `instrument()` or `PostHogMCP`. `beforeSend` can drop a value but cannot restore one. With the option off, the intent and feedback text keep their redaction, and credentials are redacted everywhere.
