- Item: issue #5084 — Local flag evaluation keeps Durable Objects alive indefinitely
- Conclusion: Confirmed posthog-node bug: local feature-flag evaluation always schedules a recurring timer, including when a shared cache says this instance should not fetch definitions.
- Labels: node, feature/flags, team/client-libraries, performance, bug
- URL: https://github.com/PostHog/posthog-js/issues/5084
- Relevant files: `packages/node/src/client.ts`, `packages/node/src/extensions/feature-flags/feature-flags.ts`, `packages/node/src/extensions/feature-flags/cache.ts`, `packages/node/src/types.ts`, `packages/node/src/__tests__/feature-flags.spec.ts`, `packages/node/src/__tests__/posthog-node.spec.ts`
- Findings: `PostHogBackendClient` creates `FeatureFlagsPoller` when a secret/personal API key is configured and `enableLocalEvaluation !== false`; local evaluation defaults on in that situation.; The Node client defaults `featureFlagsPollingInterval` to 30,000 ms and passes it to the poller.; `FeatureFlagsPoller._loadFeatureFlags()` consults `cacheProvider.shouldFetchFlagDefinitions()`. When it returns false, the poller can load cached definitions and return without requesting PostHog.; Regardless of whether definitions were fetched, cache-loaded, stale, or an error occurred, `_loadFeatureFlags()` schedules `setTimeout(() => this.loadFeatureFlags(true), this.getPollingInterval())` in its `finally` block unless stopped.; `stopPoller()` clears that timeout, and client `_shutdown()` calls `featureFlagsPoller.stopPoller()`. The public shutdown contract documents that it clears the feature-flags poller.; Existing tests verify that polling is rescheduled after a slow fetch and that stopping the poller prevents rescheduling, but do not cover a Durable Object-compatible cache-only/on-demand mode.
- Fix assessment: The immediate cause is localized, but a correct fix needs an agreed freshness policy. Disabling the recurring timer changes local-evaluation consistency, and exposing stale-while-revalidate behavior would be a public configuration/API decision. Using a Node-only timer `unref()` is not a safe assumed fix for Cloudflare Durable Objects.
