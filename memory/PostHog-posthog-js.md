- Labels: feature/replay, performance, web, team/client-libraries, needs-to-be-contributed-back, bug

- Findings: `MutationBuffer.processBufferedMutations()` puts additions with an unresolved parent or next sibling into `addList`. Its drain loop first tries one cached candidate, then otherwise scans backward from `addList.tail`, calling `mirror.getId(dom.parentNode(...))` and `getNextId()` for every candidate until one is usable. This matches the reported repeated-rescan mechanism.; `getNextId()` itself walks `nextSibling` until it reaches a non-ignored serialized sibling, so each failed candidate scan can incur additional DOM traversal.; The current code contains a prior upstream-derived optimization for re-encountered nodes (`upstream rrweb #1302`), but it only reinserts an already-added node at the end of `addedSet`; the general tail-rescan loop remains present.; The existing rrweb benchmark suite already exercises 10,000-node mutation workloads, including deep nesting and add-and-move cases, but is excluded from ordinary tests and reports durations rather than enforcing a stable timing threshold.; Existing real-browser integration tests cover child-list mutations and deferred missing-next-sibling behavior. A fix must retain their ordering semantics and add a large-batch case whose recorded output is replayed and asserted, because rrweb serialization failures can silently corrupt recordings.; The incident-risk guidance identifies rrweb serialization/snapshot correctness as a silent-corruption risk. This issue does not touch CSS serialization, but changing deferred-add scheduling requires a real-browser replay assertion rather than only a mocked-DOM or timing test.; The vendored rrweb README explicitly identifies rrweb-io/rrweb as upstream and documents contributing general changes back through an upstream fork; this algorithmic defect appears suitable for that evaluation.; No matching already-fixed entry was found in the current rrweb or browser changelogs. Later recorder work records slowest mutation-batch duration, but it measures rather than removes this repeated scanning cost.
- Fix assessment: The hot loop is localized, but its deferral logic encodes ordering requirements for parent-before-child additions, next-sibling placement, ignored nodes, moves, and shadow roots.
