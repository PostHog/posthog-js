# Evaluation contract tests

Canonical contract: [sdk-specs `9a5395c`](https://github.com/PostHog/sdk-specs/tree/9a5395c4251d3c9d4a4ceae2fa618b184c1c4099).

The tests below cover all 62 published scenarios through the JS public API. Mocked service responses test SDK behavior; they do not establish backend conformance. The transport suite also uses a real localhost HTTP server to check redirect handling. The shared SDK acceptance harness still needs management API bindings; these tests do not claim harness readiness.

`python-parity.json` was generated by executing Python SDK request/declaration code at revision `2936009887d4b23c9eb4156f77e06734e9513e78`, the spec reference revision. Its evaluation implementation matches Python main `a5b93eed7125a1ef7a9c9a442ec75487027f1f59`. The fixture covers every management method, retry policy, declarations, and an upload. It does not require Python at JS test runtime.

Regenerate deliberately with the Python checkout environment:

```sh
/path/to/posthog-python/.venv/bin/python packages/ai/tests/evaluations/generate-python-parity.py /path/to/posthog-python
```

Run through the repository Turbo graph (builds prerequisites):

```sh
pnpm turbo run test:unit --filter=@posthog/ai
```

After prerequisites are built, the focused suite is:

```sh
pnpm --filter=@posthog/ai exec vitest run tests/evaluations --coverage.enabled=false
```

Additional JS cases cover immutable snapshots and option mutation during I/O, safe integer/bigint handling, full int64 counters, UTF-16 versus code-point ordering, exact UTF-8 limits, unsupported JSON objects, prototype-shaped keys, sparse arrays, microsecond timestamps, cancellation/backoff, serialized handle operations, and reusable pending chunks. The module-load check verifies ESM/CommonJS consumers with no provider dependencies and type-checks both declaration consumers.

Intentional native adaptations: a single async client, camelCase SDK options, `timeoutMs`, `AbortSignal`, async iteration, and bigint for exact large numeric inputs. Persisted item/result declarations retain Python wire keys. Returned timestamp strings normalize to UTC without discarding fractional precision.
